# Design System: XReels

## 1. Overview

**Creative North Star: "The Private Cinema"**

XReels is a dark streaming interface built around a single conviction: the
artwork is authored for black, so the surface must be black. A zinc-900 page
(#18181b) floats in a pure-black void; the user's own bookmark collection is
presented as a streaming service catalog with rails, billboards, and a
short-video feed. Density is cinematic, not dashboard-like: large artwork,
thin chrome, generous rail scrolling, monolithic displays over quiet UI text.

The system explicitly rejects: light themes, accent pickers, gradient text,
decorative glassmorphism, SaaS white cards, neon-on-black hacker aesthetics,
and colored side-stripes. Success test: screenshot the screen; if any zone of
chrome draws more attention than the media on it, the chrome is too loud.

**Key Characteristics:**
- Dark-only, art-forward, one crimson accent used like a highlight reel.
- Bebas Neue monoliths screaming, Geist whispering underneath.
- Fast-out, long-settle expo motion; hover states everywhere, transitions under 550ms.
- Everything must survive `file://` with zero build step.

## 2. Colors

A zinc void scale from pure black to hover gray, with one crimson reserved for
status, progress, and brand moments.

### Primary
- **Crimson** (#e50914): the single accent. Badges, progress bars, focus states, brand marks, the discover billboard logo. Used sparingly; rarity is the point.

### Secondary (optional; used deliberately)
- **Amber** (#ffc425): rating chip only.
- **Teal** (#54b9c5): "explore" affordances only.
- **Success** (#46d488) / **Warning** (#ffb547) / **Danger** (#e01d29): system status, never decoration.

### Neutral
- **Void** (#000000): html background, header scrim origin, media matting.
- **Zinc Page** (#18181b): the page itself; hero vignettes end here.
- **Sunken Well** (#101012): code, masonry gaps, sunken wells.
- **Control Fill** (#1f1f23): inputs, quiet controls.
- **Hover Fill** (#2a2a2e) / **Strong** (#3a3a3f): interactive fills.
- **Card Void** (#0b0b0b): cards and popovers.
- **Glass Panel** (#141416) / **Strong** (#1c1c1f): opaque near-black menus, toasts, sheets.
- **Ink** (#f8f8f8): primary text; **Muted** (#9b9b9b) for secondary text. Muted is lifted to #9b9b9b so it still clears 4.5:1 on the raised surfaces (segmented tracks, cards) and not only on the page.
- **Hairline** (#222222): borders and dividers; stronger hairlines at rgba(255,255,255,.15).

### Named Rules
**The One Crimson Rule.** #e50914 appears only where the system means it:
brand, focus, progress, live status. If a screen glows red on a whim, it is wrong.
**The Black Mat Rule.** Media never sits on gray. Artwork mats directly on
#000 or #18181b; mid-gray frames are forbidden.

### The White-Alpha Ladder
Depth on this canvas comes from one pigment — white at low opacity — never from
new grays. Fills run `white-o0055` → `white-o035` (resting panels, tracks,
dividers); hairlines and rims `white-o008` → `white-o02`; text on artwork
`white-o055` → `white-o092`; chrome over media uses the same ladder so a pill on
a poster matches a pill in a menu. Opacity is the only knob: do not introduce a
second hue to separate two layers.

## 3. Typography

**Display Font:** Bebas Neue (single weight 400, never faux-bolded)
**Body Font:** Geist (variable 300–800)
**Label/Mono Font:** Geist Mono (400–600)

**Character:** A headline voice that screams like a marquee over a body that
whispers like a service manual. Display is only ever crimson, white, or black
on media; body text caps at comfortable measure on dark surfaces.

### Hierarchy
- **Display** (400, clamp(2.2rem→3.4rem), line-height 1, tracking 0.015em): billboard titles, feature headings, splash. Bebas only; one weight.
- **Eyebrow** (400, 11px, tracking 0.16em, uppercase): section labels, colophon text.
- **Body** (400, 14px, line-height 1.55): paragraphs, descriptions, meta rows.
- **Label** (mono 500, 11px): metrics, timestamps, keyboard hints, data readouts.

### Utility Ramp
Between those four anchors sits one deliberate half-step ramp, because the UI runs
dense: 11 / 12 (micro-labels and captions), 12.5 / 13 (captions and meta rows),
15 / 15.5 / 16.5 (list titles), 17–28 (card and panel titles), 30–40 (page and
section heads), 48–120 (billboard display, clamp endpoints), 168 / 224 (Top-10
ghost numerals). Steps exist for a reason — never invent a size between them.

### Named Rules
**The Single Weight Rule.** Bebas Neue ships one weight; faux-bold, faux-italic,
and per-letter scaling are forbidden. Hierarchy through size and tracking only.

**The Legibility Floor.** Functional text — anything the user reads in order to
act, including letterspaced micro-labels and badges — never renders below 11px.
The old 8.5 / 9 / 9.5 steps are retired: they failed on high-DPI screens and on
small viewports, and "it is on the ramp" is not an exemption. When a label needs
to be quieter than 12px, buy the quietness with tracking, weight and colour,
never with size. The ramp now starts at 11px (`label` and the legacy micro
aliases); `micro` and `caption` use 12px.

## 4. Elevation

Dark-system layering is done tonally (void → page → well → hover), not with
color inversion. Shadows are deep, black, and genuinely rare: they exist to
separate floating media and chrome from the artwork behind them, never to
signify importance.

### Shadow Vocabulary
- **Tier 1** (`0 2px 10px rgb(0 0 0 / 0.4)`): small controls raised off media.
- **Tier 2** (`0 12px 34px rgb(0 0 0 / 0.55)`): menus, hover-cards, sticky chrome.
- **Tier 3** (`0 24px 64px rgb(0 0 0 / 0.7)`): modals, viewer surfaces, splash.
- **Card** (`0 22px 44px rgb(0 0 0 / 0.6)`): tile hover lift only.

### Named Rules
**The Floating Rule.** A surface at rest casts no shadow. Shadows appear only
on lift (hover, focus, dialog, preview) and return instantly on settle.

## 5. Components

### Buttons
- **Shape:** full pill (999px), padding 10px 20px.
- **Primary (pill):** white fill (#f8f8f8) on black text; the "Explore/Play" CTA. Hover dims to 85% and lifts 1px.
- **Accent (pill):** crimson fill, white text; reserved for brand-level actions (open on X, splash CTA).
- **Ghost:** transparent, white/14% hairline fill; live in panels and menus.
- **Focus:** crimson ring (2px, offset 2px); never removed, only styled.

### Chips
- **Style:** glass fill rgba(255,255,255,.14), white text, 999px, 4px 10px.
- **State:** selected = crimson fill with white text; unselected = neutral glass.

### Cards / Containers
- **Corner Style:** 10px radius for artwork cards; 14px for billboards; 6–8px for chrome; 2–3px only for hairlines, progress fills, and heat cells.
- **Background:** card void #0b0b0b or transparent over media with black scrims.
- **Shadow Strategy:** see Floating Rule; lift 2–4px + Tier 1 shadow on hover.
- **Border:** 1px #222222 hairline on chrome; no borders on artwork.

### Inputs / Fields
- **Style:** #1f1f23 fill, #222222 1px border, 8px radius, Ink text, mono placeholder.
- **Focus:** crimson 2px ring; error states use #e01d29 copy, never red borders on the field.

### Navigation
- A fixed, safe-area-aware header: black scrim at rest, an opaque near-black surface after scrolling (no full-width backdrop blur).
- Desktop: text links in a near-black rounded track, a transform-driven active surface, and a short crimson active marker. Search gains a text label and shortcut hint on wide screens; compact widths keep the icon. Tablets retain horizontally scrollable, 44px page chips.
- Phones below 768px: a 56px top bar plus a 64px opaque inset navigation dock, 10px from the edges with the home-indicator inset added. Reserve 84px plus the safe-area inset below content. A single moving neutral surface with a short crimson cap indicates the selected destination; labels stay fixed and truncate rather than wrap. The bar carries the wordmark at rest and cross-fades to the destination name once content scrolls; detail pages keep Back plus that name. Tapping the current destination returns its page to the top.
- Phones hold one bar action (Search). Sound is global rather than page chrome, so it lives in More alongside the command palette. Discover, Library, Watch, Collections, and More are always findable; More retains Creators, Insights, Import, Settings, the command palette and sound. Its sheet exposes expanded state, keyboard navigation, focus return, a labelled Cancel, and drag-to-dismiss from its handle.
- Search is a mode on phones, not a floating box: it replaces the bar's contents, adds a labelled Cancel that holds a 44px target, leaves on Escape, and dims the page and dock behind it. Enter navigates; Cancel never does.
- Phones in short landscape (below 768px tall, up to 1023px wide) keep the same dock in a compact 56px form with a 48px bar, because the landscape chip rail cost more vertical room than the content could spare.
- Watch remains immersive and has its own Back control. Bottom navigation must not cover bulk actions, toasts, or page endings.
- Primary links expose `aria-current="page"`; search is a visible action and its closed form is actually hidden.
- Keyboard-first: ⌘K palette shortcuts remain annotated in labels (mono).

### Touch Targets
- **44×44 CSS px** is the XReels target for primary controls, navigation, segmented choices, and media controls. A smaller drawing may use a transparent hit-area extension (for example the tile's 30px “More” circle has a 44px hit area).
- On touch, inputs and selects are at least 44px tall and use 16px text to avoid iOS focus zoom. Textareas retain their multiline height.
- Heatmap days and SVG chart marks are dense data visualizations, not evidence of universal 44px compliance. The audit reports them separately for further accessibility review.
- Touch tile metadata is a visible 44px creator row, never a hover requirement. Desktop hover-only metadata is supplementary, inert and hidden from assistive technology until hover or keyboard focus reveals it. Masonry geometry reserves the actual metadata height.

### Video Player
- **The scrubber is a control, not a hairline.** A thin buffered/played track sits under a native range input with a visible thumb and a real 44px hit band. Both Watch and Viewer support touch dragging, keyboard ±5s, Home/End, and spoken elapsed/total values.
- **The clock stays visible on phones.** Elapsed and total time appear where space permits; the smallest Watch layouts keep elapsed time.
- **Double-tap seeks on touch.** Left 40% −10s, right 40% +10s, centre still stars. Feedback stays inside the viewport. Desktop double-tap retains the existing Star behaviour.
- **Playback is explicit.** A play/pause button and speed choice (0.5×–2×) live on the Watch surface. Muted autoplay offers “Tap for sound”. Fit/fill, PiP, and Up next remain available through Player options on phones.
- **Gestures have lifecycles.** Carousel horizontal drags do not seek; vertical swipes navigate the feed. Cancellation, route changes, virtualisation, and hold-to-speed release clear pending work. Only the active cell's controls are focusable. Recovery Next is manual, independent of auto-advance; Retry creates a fresh player attachment.
- **Landscape is its own layout.** Short-screen recovery cards retain their width cap, use a compact action row, and do not overlap the side rail. Viewer controls give the seek bar its own row on touch-sized screens.
- **Respect reduced motion.** Feedback remains visible without a scale animation; no new animation may bypass the global motion preference.

### Signature Components
- **Rail:** horizontal scroller of tiles with 8px gaps, directional arrow scrims at ≥1024px, snap scrolling, no visible scrollbar by default.
- **Billboard:** desktop artwork and copy retain their cinematic treatment. On phones, a compact artwork card uses a two-line title, one primary Play/View action and an icon for details; it leaves the first shelf within reach.
- **Watch feed:** a virtualised, immersive video stack; only one video plays at a time. Default autoplay remains muted. Thin crimson progress is paired with a usable thumb, clock, and explicit playback controls.

## 6. Do's and Don'ts

### Do:
- **Do** mat every artwork on pure black or #18181b with matched scrims under text.
- **Do** keep motion on `cubic-bezier(.22,1,.36,1)`; fast out (200ms), long settle (550ms).
- **Do** annotate every keyboard affordance in Geist Mono.
- **Do** use the crimson ring for focus across the whole app; one focus language.
- **Do** honor `[data-motion="reduce"]` for every animation shipped.
- **Do** keep functional text at 11px or above, and primary touch controls at 44×44; review dense chart marks separately.

### Don't:
- **Don't** introduce a light theme or accent picker; the artwork is authored for black.
- **Don't** use gradient text (`background-clip: text`), side-stripe borders, or decorative glass.
- **Don't** build identical icon-card grids; layouts are rails, billboards, and masonry, not feature-card templates.
- **Don't** open a modal when an inline surface exists.
- **Don't** let chrome outshine media: if the screenshot's brightest zone is not the artwork, fix the chrome.
- **Don't** faux-bold Bebas Neue or letter-space body text.
- **Don't** nest a card inside a card; a section is a surface, and what lives in it is a row, not another box.
- **Don't** set crimson text on a near-black surface with #e50914 — it only reaches 4.2:1 there. Use `crimson-tint` (#ff6b74) for crimson *text*; reserve #e50914 for fills, borders and marks.
